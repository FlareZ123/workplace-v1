# K04: exact MT19937 regular-row fit cannot predict the recovery tail

**Agent 38, 19 October 2026. Mathematical counterexample and locally executed reproducer.** No K04 candidate was recovered. Neither `acceptance.json` nor `verify.py` is read, replaced or tested.

## Original source and model claim

The source-pinned original `evidence/print/spool-reconstruction.log` (SHA256 `7d71d8bef7f01596e705ac14e24c5c4352042512b3088125afca40f3841b6083`) has 128 standard `+00:00` rows, followed by five `Z`-timestamp RECOVER-tail rows. Each PAYLOAD is 16 bytes. Model the regular payload stream in file order as four little-endian 32-bit outputs per row from Python's MT19937 `random.Random.getrandbits(32)`. **This is deliberately hypothetical; no original record claims the printer used MT or continuous state between cohorts.** We test whether merely fitting a purported MT generator to every intact regular payload would *mathematically imply* any held-out tail bytes.

## Constructive result, before original K04 commitment

The 128 regular records expose exactly **512** 32-bit outputs. MT19937 uses an array of **624** 32-bit state words before twisting. Its four-step output tempering transform on a 32-bit state word is invertible.

1. Untemper each of the 512 observed regular outputs to recover exactly the first 512 state words that a `setstate`-admissible MT model may start with.
2. Fill the remaining 112 state words with all zeros to form state A, and with all `0xFFFFFFFF` to form state B. Both states reproduce **512/512** source-observed regular words *bit-for-bit*.
3. A predicts the immediately subsequent four words as `00000000` each; B predicts those words as `6FE01BF8` each. Their predictions differ already at the first byte of the first Z-tail payload. The actually retained first tail 16 bytes decode as `214F3ECD B12FDB6A A92ADA80 A4F7330B` in the same little-endian word orientation; neither state was fitted to these.
4. Deliberately *retrofit* positions 512–531 of the remaining unobserved state with the inverse-tempered actual 20 tail words and fill the final 92 state words with zero. This model reproduces **all 532/532 outputs from all 133 retained rows**, exactly. This is constructed **after seeing** the tail, and it has *no predictive significance*.

Implementation: [`k04_mt_identifiability.py`](k04_mt_identifiability.py), standard-library, original spool SHA-pinned; assertions check both exact training reconstructions, differing tail predictions and full post-hoc interpolation. The script ran locally on the unmodified supplied 43-member ZIP.

## Discriminant and limitation

This proves a sharp **model identifiability failure** for an MT19937 generator with unconstrained `setstate`-admissible state and the stated contiguous-word and byte-orientation assumptions. A perfect fit to 128 regular printer rows in this class cannot establish **even the first RECOVER-tail word**, much less repair the selected K04 attempt-2 payload. The other 112 state words are unobserved when tail prediction begins, so an in-sample `532/532` fit to all records is equally noninformative.

This finding does **not** establish that any printer used MT, that the actual tail was generated by a continuous stream, or that a generator restricted to a known scalar seed cannot be recovered. A documented seed/seed derivation or **more than the existing 512 contiguous regular words** would materially change the modeled degrees of freedom. No such source relation is retained. Existing Agent10/42 short-seed and held-out PRNG checks address different, more constrained claims.

**Cracking consequence:** before anyone treats a printer-model exact training fit as a K04 recovery lead, require a genuine out-of-sample prediction on an untouched Z-tail payload, and an original-source reason why the model transfers from `+00:00` regular rows. Under this tempting MT class the input itself admits arbitrary tail outcomes; it cannot select a corrected coupon or source layer. This is a new no-inference theorem for a named source-model class, not a successful K04 correction or a general impossibility proof. The untouched K04 commitment remains unresolved.
